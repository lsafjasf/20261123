# 帧源 FrameTrace

视频来源水印与取证工具。创建者编号会被编码进每一帧的低可见多帧水印；核验时会从
裁剪、缩放、转码或截短的片段中搜索水印几何，给出编号、置信度和可解释证据。

工具只做来源标识，不包含任何去除他人水印的功能，也不使用固定样例、云端服务或
第三方运行时库。

## 运行

需要 Node.js 24+ 与现代 Chromium / Edge 浏览器。

```bash
npm start
```

打开 <http://127.0.0.1:4173>。服务端直接执行 `.ts`，浏览器端模块由 Node 标准库
`module.stripTypeScriptTypes` 按需转译，无构建步骤、无 npm 依赖。

```bash
npm test
```

测试覆盖载荷回环、Hamming 纠错、CRC 位损坏、裁剪 + 缩放 + 噪声检测、普通画面
误报控制和跨帧合并。

## 使用流程

1. 在“标记来源”中载入母版视频，输入 1 – 4,294,967,295 的创建者编号。
2. 选择隐蔽 / 均衡 / 强韧写入强度，预览首帧水印效果。
3. 生成来源副本。Canvas 逐帧渲染、WebAudio 路由音轨、浏览器媒体编码器输出 WebM。
4. 在“验证片段”中载入搬运或二创片段，选择灵敏度并核验。
5. 命中时读取创建者编号、置信度、同步位、CRC24、Hamming 纠错、网格锚点和逐帧证据。

导出为实时媒体编码，视频有多长，浏览器就需要播放/渲染多久。文件不离开本机。

## 编码结构

- 每个水印块为 `12 × 8 = 96` 个亮度单元，块在画面内周期重复。
- `16 bit` 同步码用于几何相位定位。
- `32 bit` 创建者编号采用 `Hamming(7,4)` 编码，可纠正片段中每 7 位一组的单比特错误。
- `24 bit` CRC 覆盖版本和编号；检测端允许一个 CRC 位损坏并记录纠错情况。
- 整幅符号序列再做固定伪随机白化，避免形成易识别的固定图案。

检测器枚举单元尺寸、亚像素偏移和 96 种相位，对多尺度网格聚合软证据；跨帧阶段
会按几何聚类并合并位级读数，降低压缩噪声与运动纹理的影响。

## 技术栈

- TypeScript + Node.js 标准库
- Canvas 2D / `ImageData`
- WebCodecs 能力探测与编码器预检
- WebAudio `MediaElementAudioSourceNode` + `MediaStreamAudioDestinationNode`
- MediaRecorder 媒体封装
- MediaSource 能力探测

无第三方依赖、无构建工具、无远程请求。`package.json` 中依赖为空。

## 边界

水印强度是可见性与鲁棒性的折中。极低码率、强去噪、黑场、整块水印区域被完全遮挡
或只保留极少帧时，置信度会下降；达不到阈值时工具明确返回未命中，而不是猜测编号。
工具不提供去除、擦除或规避他人水印的接口。
