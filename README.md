# Echo Takes

本地优先的单声道人声 **重复 take 检索与人工复核工作台**。它面向连续数小时的人声录音：自动寻找相隔很远、旋律轮廓相似但演唱细节不同的片段，再由制作人逐组确认。

## 运行

需要 Node.js 22.13 或更高版本。项目没有 npm 依赖。

```bash
npm run dev
# 打开终端输出的 http://localhost:4173
```

其他命令：

```bash
npm test       # 音高门、匹配、噪声拒绝、清单编码测试
npm run check  # 检查所有 TypeScript 模块可被 Node 类型剥离
npm run build  # 生成可静态托管的 dist/
```

`dist/` 中只有浏览器模块、HTML 和 CSS，不需要构建工具或外部 CDN。

## 工作流

1. 拖入 WAV / MP3 / M4A / OGG，或点击“演示工程”生成一段 104 秒、包含 3 个相似 take、1 段干扰旋律和宽带噪声的演示录音。
2. 调整最短重复长度、最小间隔、轻微移调容差和相似度门槛，点击“重新检索”。
3. 在候选组列表中逐组复核：A/B 波形与音高轮廓可叠加对比，每个 take 都能单独试听。
4. 点击“确认重复”或“排除本组”。确认过的组才会进入命中清单。
5. 点击“试听串烧”按时间顺序只播放已确认片段；点击“导出清单”下载 M3U8 与 JSON。

快捷键：`J` / `K` 切换候选，`Enter` 确认，`X` 排除，`Cmd/Ctrl + Enter` 重新检索，`Esc` 停止播放。

## 算法

- **单声道特征提取**：8 kHz 分析域、1024 点 Hann 窗、20 Hz 帧率。频谱谐波梳用于基频估计，同时计算 RMS 与频谱平坦度。
- **空白/噪声拒绝**：只有同时满足能量、音高置信度、频谱平坦度与 voiced 覆盖率的窗口才进入候选池。宽带噪声即使重复，也会因平坦度和音高对比度不足被丢弃。
- **旋律描述子**：每个窗口重采样为 24 点、以中位音高归零的相对旋律轮廓；候选首轮按粗轮廓筛选，随后用约束 DTW 吸收轻微速度与换气差异。
- **远距约束**：匹配两段的起始时间差必须不小于“最小间隔”；相邻命中会合并成完整片段，避免把同一处重复登记多次。
- **移调容差**：候选的音高中心差按八度折叠后必须落在设置范围内，结果同时报告实际半音偏移。
- **长录音**：特征数组与波形峰值按固定密度保存；候选窗口步长会根据录音长度自适应放大，避免小时级录音产生无上限的滑窗数量。

匹配在 Web Worker 中运行，主界面保持可交互。分析、播放、绘制和导出均在本机完成，不上传音频。

## 命中清单

M3U8 使用 `#EXTVLCOPT:start-time` / `stop-time` 标记每个命中片段，只引用原音频文件一次。将音频与 M3U8 放在同一目录，可用 VLC 等支持扩展 M3U 的播放器按命中片段顺序播放。JSON 还包含总命中时长、每段分数以及起止秒数，便于后续自动化处理。

演示工程导出时会一并生成 `echo-takes-demo.wav`，确保示例清单可直接播放。

## 结构

```text

src/shared/     跨线程数据类型
scripts/        零依赖构建与静态服务器
tests/          Node 内置测试
```
