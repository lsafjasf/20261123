# SIX/CUE 声场导播台

六机位直播的离线切换工作台。它把六路现场声的能量、突发起音和持续领先关系变成可解释的机位建议，并用最短停留、确认窗和 dB 迟滞阻止频繁乱切。导播始终可以接管、撤销、补标记；每条建议都保存六通道音频证据，可回放、看曲线、试听。

## 运行

要求 Node.js 22.13+，项目没有 npm 依赖，也不需要联网。

```bash
npm start
# http://127.0.0.1:4178
```

其他命令：

```bash
npm test       # 推荐状态机、音频特征、场景回归
npm run build  # 使用 Node 内置 TypeScript 类型擦除生成浏览器模块
npm run check  # 检查生成模块、静态资源与离线约束
npm run dev    # 修改源码后自动重建并重启
```

## 功能

- 六路 Canvas 预监和节目输出：全景、主机位、两侧底线、网侧、反打，共用同一球路与时刻。
- 六通道 WebAudio 分析：RMS / dBFS、滚动底噪、起音强度、次席差距、持续领先。
- 安全切换：默认 `2.4s` 最短停留、`650ms` 确认窗、`4.5dB` 迟滞，可在界面实时调整。
- 自动 / 提示两种模式。点击任意预监、按 `T` 或采纳提示都会进入导播接管；可一键恢复。
- 完整会话时间线：建议、自动切换、手动切换、撤销、标记均保留。
- 证据回放：每条记录保存建议前 2.4 秒与后 2.4 秒的六通道能量/起音数据，带游标回放、来源说明与证据试听。
- 所有状态和音频处理都在本机。无外部字体、图片、CDN、云服务或运行时依赖。

## 操作

| 操作 | 方法 |
| --- | --- |
| 切换机位 | 点击预监，或数字键 `1`–`6` |
| 接管 / 恢复 | `T`、`接管` 按钮、点击任意预监 |
| 撤销上一次切换 | `Z` |
| 补标记 | `M`，选择类型并填写备注 |
| 查看音频证据 | `R`、`证据回放` 或点击时间线记录 |
| 回放 / 暂停 | 证据弹窗内按空格或点“播放” |

## 判断逻辑

每 42ms 对六路音频采样一次：

1. 计算每通道 RMS，转换为 dBFS，并用慢速滚动底噪估计起音强度。
2. 焦点分数为 `能量 + 起音 × 起音权重`；同时检查候选通道是否真实领先次席。
3. 候选必须连续领先超过确认窗，且比当前机位高过迟滞阈值。
4. 自上次切换起必须满足最短停留，才允许产生建议或自动切换。
5. 自动模式执行切换；提示模式只记录建议。任何手动操作都会暂停自动决策并重新计算停留时间。

证据链以 96 秒环形缓冲保存，事件创建时截取前后窗口，后续 2.4 秒持续补帧，因此回放能看到建议被触发前后的完整关系。

## 结构

```text
server.ts             Node 标准库静态服务器
src/domain.ts         机位、配置、事件与证据类型
src/scenario.ts       可重复的六机位球路与声场演练
src/audio-metrics.ts  RMS / 起音特征
src/audio.ts          WebAudio 六通道合成、分析、证据试听
src/engine.ts         最短停留、迟滞、持续领先与确认窗状态机
src/renderer.ts       六视角 Canvas 球台渲染
src/charts.ts         六通道能量 / 起音曲线
src/main.ts           导播界面、时间线、回放与控制
tests/                零依赖 Node 测试
```

内置演练场让验收过程可重复，不依赖外部素材。现场音源接入边界集中在 `src/audio.ts`；推荐、证据、时间线和回放层不依赖具体音源生成方式。
