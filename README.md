# SeamLab · 游戏录像水平撕裂取证

玩家上传的游戏录像偶尔会出现一条水平错位，像画面被撕成上下两半。SeamLab 在本地逐帧检查
**帧内水平断层**与**跨帧重复/时差**，把真正的采集不同步、编码块错误和游戏故障特效分开，
并允许逐帧放大审阅、人工复核与导出分类统计。

整个工具离线运行、零第三方依赖：TypeScript + Node.js 标准库 + 浏览器原生
WebCodecs / WebAudio / Canvas；`MediaSource` / WebCodecs 能力会在导入面板中探测并显示。

## 启动

```bash
npm start
# http://127.0.0.1:4173
```

首次打开会自动生成并分析一个 168 帧的本地合成样例，包含：

- 4 帧真实采集水平撕裂
- 2 帧 16 px 宏块损坏
- 5 帧带横线爆发的游戏故障特效
- 其余帧保留静态扫描线、HUD 横线与运动画面，作为误报基线

也可以点击右上角“导入录像”，选择本地 MP4 / WebM / MOV。视频只进入当前浏览器内存。

## 检测逻辑

分析器先缩放到 384 px 宽的亮度平面，再为每帧建立多路证据：

1. **帧内断层**：扫描水平边界，使用缝隙邻域的窄窗带估计水平位移；要求位移在整幅宽度上
   获得足够行/列支持，并且位移后缝隙残差明显下降。
2. **跨帧重复**：保存上下半幅签名，在最近帧中分别寻找最佳时差；上下半幅回溯到不同帧时，
   形成 `crossFrameSkew` 证据。
3. **横线基线**：统计全宽高频横线密度，并维护片段自身的滚动基线。持续扫描线、HUD
   横线不会被判成撕裂，只有密度突然抬升且跨帧复现时才倾向游戏特效。
4. **块状错误**：检查 4–24 px 周期在 X/Y 两轴的网格一致性，以及局部块均值/纹理异常。
   块错误与撕裂同强时优先归为编码块，避免把宏块断边误当采集错位。
5. **分类顺序**：真实撕裂必须同时满足有效位移、缝隙残差下降和整幅支持；之后才考虑
   游戏特效、编码块和“证据不足”。

核心实现见 `src/core/analyzer.ts`，纯函数图像操作见 `src/core/image.ts`。

## 审阅与导出

- 时间线筛选：撕裂 / 编码块 / 特效 / 存疑。
- 画布支持 1×、2×、4×、8× 缩放，放大后可拖拽；右下角 4× 透镜跟随鼠标查看缝隙。
- 每帧展示三类分数、位移支持度、缝隙增益、跨帧偏斜、横线密度与块状异常。
- “排除路径”列出为什么当前帧不是另外一类，便于人工快速复核。
- 人工复核可覆盖自动分类，统计与导出立即更新。
- 导出逐帧 CSV、完整 JSON 报告和五类汇总 CSV。CSV 带 UTF-8 BOM，Excel 可直接打开。

## 项目结构

```text
src/core/analyzer.ts   逐帧检测、分类与统计
src/core/image.ts      缩放、亮度、行差、跨帧签名
src/core/export.ts     CSV / JSON 报告
src/server.ts          静态服务 + Node 原生 TS 即时转译
web/app.ts             审阅台状态、时间线、缩放、导出
web/demo.ts            程序化游戏画面与故障注入
web/ingest.ts          WebCodecs / WebAudio / Canvas 导入管线
web/styles.css         离线界面样式
test/                  检测与导出测试
```

浏览器端 `.ts` 模块由 Node 24 的 `module.stripTypeScriptTypes()` 在本地即时转译，
没有构建步骤，也不会访问网络。

## 验证

```bash
npm test
```

测试覆盖：真实整幅撕裂、持续高频扫描线不误报、网格块错误、跨帧复现游戏特效，
以及逐帧 CSV / JSON / 分类统计导出。

## 限制

- 非撕裂但完全不可解码的损坏帧仍会进入“证据不足”，不会被强行归类。
- 极度模糊或大面积纯色画面缺少可比较纹理，位移置信度会自然降低。
- 导入采用浏览器能解码的格式；不支持的解码器会直接提示，不会上传到服务器。
