# 汇报厅扩声啸叫抑制演示

从麦克风/素材信号中识别**持续窄带增长**（啸叫前兆），在风险升高前受控启用陷波器，
支持逐项旁路与自动恢复。纯 TypeScript + Node.js 标准库 + WebAudio + Canvas，
零第三方运行时依赖、无云端。

## 运行

```bash
npm run build     # 编译 TypeScript → public/js
npm start         # http://localhost:8080/
npm test          # 无头仿真测试（Node 标准库，验证检测器）
```

## 使用

- 选择程序生成素材（扫频 / 持续长音 / 合成讲话 / 啸叫注入 / 混合）播放，
  或点「使用麦克风」实测（localhost 下可用，已关闭浏览器自带降噪以保证检测原始性）。
- 频谱图上：橙色竖线 = 活动陷波，红色三角 = 触发频率标记。
- 陷波器表格可逐项旁路；「恢复中」状态带进度条，无风险持续 5s 后经 2s 淡出释放。

## 检测原理（src/detector.ts）

对 4096 点 FFT 频谱（20 帧/秒）逐 bin 判定，需同时满足：

- **持续增长**：12 帧（0.6s）滑动窗线性回归斜率超过门限（随灵敏度 2.5~6 dB/s）；
- **窄带突出**：高于邻域中位数 7~12 dB（啸叫是单频自激）；
- **增长一致性**：窗内 ≥70% 帧单调上升（排除颤音长音、讲话音节的起伏）；
- **峰位驻留**：窗内 ≥70% 帧保持同一窄带峰（排除扫频与移动的共振峰）；
- **宽带守卫**：单 bin 斜率须超过全带平均斜率 2 dB/s（排除讲话 onset 全带齐涨）；
- **起始电平守卫**：窗口前段须已有信号（排除从无声突起的 onset）。

## 信号链与延迟

```
素材/麦克风 → inputGain → [陷波链 NotchBank] → monitorGain → 扬声器
                 |                |
                 +-> preAnalyser  +-> postAnalyser（仅抽头，不在监听路径）
```

陷波为 BiquadFilterNode（Q=12），群延迟 <1ms；分析器是旁路抽头，
监听延迟仅由输出设备决定（`latencyHint: 'interactive'`）。
陷波介入/旁路/恢复均用 0.15s 交叉淡化，避免爆音。

## 文件

- `src/material.ts` — 程序生成测试素材（确定性 PRNG，可复现）
- `src/detector.ts` — 窄带增长检测器
- `src/notches.ts` — 陷波槽位管理（受控介入、逐项旁路、自动恢复）
- `src/main.ts` / `src/ui.ts` — 音频图装配与界面渲染
- `server.js` — Node 标准库静态服务器
- `test/simulate.mjs` — 无头仿真：STFT 喂检测器，断言啸叫命中且扫频/长音/讲话零误报
